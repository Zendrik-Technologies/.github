## 07 — ENGINEERING PRINCIPLES

### Build for the problem

Technology should serve the problem — not become the problem.

### Keep systems understandable

Good architecture should make future changes easier, not harder.

### Ship useful software

A working product creates more value than an impressive specification.

### Prefer evidence over assumptions

Product decisions should be grounded in real requirements, technical constraints and observable behaviour.

### No unnecessary complexity

Use the simplest architecture that can responsibly solve the problem.
